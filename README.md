# Adventure TCG テスト卓

ブラウザ向けTCGエンジンの縦切りテスト版です。

## 起動

Node.jsが利用できる環境で、プロジェクトのルートから実行します。

```powershell
npm.cmd start
```

表示された `http://127.0.0.1:8080` をブラウザで開きます。

## 現在できること

1. 2人分のメインデッキを準備する
2. 敏捷が高いプレイヤーを先攻にする
3. 初期手札を5枚引く
4. 初期リソースを3枚置く
5. 任意でマリガンする
6. フェイズをメインフェイズまで進める
7. 手札のイベント「旅支度」を使用して2枚引く
8. 使用したイベントを墓地へ送る
9. ターン終了後、次のプレイヤーへ交代する
10. 全依頼への参加宣言を確定後、依頼を1件ずつ選んで準備・解決する
11. 依頼報酬のリソースで冒険者デッキの特徴を使用する
12. レベル11に到達して勝利する
13. 山札が0枚になった時、墓地をシャッフルしてデッキを再構築する
14. 魔法・特技・特徴で回復、依頼能力補正、常時能力補正、タグを得る
15. レベル・能力値・タグの有無によるカード使用条件と依頼参加条件を判定する
16. プレイヤーまたはカードを選び、保留したカード効果を選択後に再開する
17. 場に出た時・場を離れた時・自分のターン開始時・終了時の誘発効果を解決する
18. P2P向けのJSONコマンド入力と閲覧者別公開状態出力を提供する
19. 冒険者またはカードへ期間付きの名前付き状態を付与・解除する
20. 継続効果によるダメージ軽減・無効、報酬増加、任意のMP置換を処理する
21. ホーム画面からデッキを構築・保存・JSON入出力する
22. ルームIDまたは手動接続コードを使い、WebRTCによる2人P2P対戦を行う

## テスト

```powershell
npm.cmd test
```

エンジンテストに続いて、実ブラウザを使うUI基本操作テストを実行します。UIテストでは通常のゲーム操作に加え、2画面間のWebRTC接続、参加者コマンドの往復、状態同期、相手の手札の秘匿も確認します。

個別に実行する場合は次のコマンドを使用します。

```powershell
npm.cmd run test:engine
npm.cmd run test:ui
```

`test:engine` は `js/tests` 直下の `test*.js` を自動検出します。新しいエンジンテストを追加する際に `package.json` へファイル名を追記する必要はありません。UIテストはブラウザ起動を伴うため、専用の `test:ui` として分離しています。

UIテストには端末へインストール済みのMicrosoft EdgeまたはGoogle Chromeを使用します。標準の場所にない場合は、環境変数 `UI_TEST_BROWSER_EXECUTABLE` にブラウザ実行ファイルの絶対パスを指定してください。

トランザクションの巻き戻し、部分成功、再現可能な乱数、定義データ検証、選択後の処理継続、複数依頼の固定進行はエンジンテストで検証します。

## 現在の制限

- カード使用・依頼参加条件はレベル、能力値、必須タグ、禁止タグに対応しています。
- 効果の発動条件・コマンド・対象はサンプルカードに必要な範囲のみ実装されています。
- デッキ保存はブラウザ内保存です。対戦履歴や進行中ゲームの再開には未対応です。
- P2P接続はルームID方式を既定とし、手動コード方式も使用できます。切断再接続、観戦、TURN中継、ホスト不正対策には未対応です。

## VercelのルームAPI設定

Vercelへ配置する場合、ルーム情報の一時保存にUpstash Redisを使用します。
Vercel MarketplaceでUpstash Redisを接続し、次の環境変数を設定してください。

| 環境変数 | 内容 |
|---|---|
| `UPSTASH_REDIS_REST_URL` | Upstash RedisのREST URL |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash RedisのRESTトークン |
| `SIGNALING_SECRET` | 32文字以上のランダムな秘密文字列 |
| `SIGNALING_ALLOWED_ORIGINS` | APIを別ドメインに置く場合だけ、許可するオリジンをカンマ区切りで指定 |

ローカルの`npm.cmd start`ではメモリStoreを使用するため、Redis設定なしで
ルームID接続を試せます。ルームの有効期限は10分です。

APIの仕様と保存先の境界は
[P2Pシグナリング境界](docs/p2p-signaling-boundary.md)を参照してください。

実装状況とルール差分の詳細は [ルール実装監査](docs/rules-implementation-audit.md) を参照してください。
カードJSONへの条件指定方法は [カード条件の定義形式](docs/card-requirements.md) を参照してください。
効果対象の指定方法は [カード効果の対象定義](docs/card-targets.md) を参照してください。
Vercel Preview、Upstash Redis、TURNを使う本番通信の設定と検証手順は [M3 通信の本番安定化](docs/m3-production-networking.md) を参照してください。
