## 正規本文へ統合した改定事項

- 冒険者デッキを非公開情報へ統一した。
- メインデッキ40枚以上・上限なし・同名4枚、冒険者デッキ15枚・同名4枚・冒険者1枚を明記した。
- 装備品の能力値修正は依頼中だけ適用し、装飾品の修正は継続適用する。
- 発注者は自動参加せず、自分の次の依頼フェイズの参加宣言中に参加を選べる。
- 参加宣言は任意には取り消せないが、カード効果では参加状態を解除できる。
- 生命超過時は、超過量までリソース・装備品・装飾品・設置済みアイテムを墓地へ送り、候補不足なら可能な枚数だけ送る。その後ダメージを現在の生命に合わせる。魔法・特技・特徴は候補外。
- 魔法は育成時に場へ置き、依頼準備中の起動時にMPを支払う。同じプレイヤーは同名魔法を1依頼につき1回だけ使用できる。
- アクティブ特技・特徴は依頼準備中に裏向きになり、次の自分ターン開始時に表向きへ戻る。依頼限定修正はその依頼の解決後に消える。
- アイテムは設置後、使用時に墓地へ送る型と、裏向きになり次の自分ターンに戻る型を持つ。
- 依頼報酬は参加者数で均等割りして各自切り上げ、成功時に発注者が追加で1枚引く。
- 依頼フェイズを `参加宣言 → 依頼1件選択 → 準備 → 攻略 → 次の依頼` に固定した。
- 同時誘発は1件なら自動解決し、複数ならターンプレイヤーから時計回りに各所有者が順番を決める。
- デッキ検索後はシャッフルし、公開したカードは効果の指定に従ってデッキの上または下へ戻す。
- MP消費の置換を任意選択とした。

## 正規ルールに対する残りの実装差分

1. P2Pの切断後の試合復帰、観戦、状態署名、ホスト不正への対策は未実装。TURN設定経路は実装済みだが、実サーバーと異なる外部回線での検証は未完了。
2. P2Pの乱数はホストが決定する。双方による乱数合意や検証可能な乱数には未対応。

## 現在確認できる設計上の問題

依頼フェイズ・依頼解決の段階は定数化済み。効果定義は現在実行可能な条件・トリガーだけを受理し、継続効果専用コマンドとの組み合わせも読込時に検証する。

カード処理結果には`committed`と`postProcessingResult`を設け、本体確定と後処理の完了を分離した。状況起因処理が20反復以内に安定しない場合は例外ではなく`STATE_BASED_ACTION_LOOP_LIMIT`と反復別診断を返す。

依頼中の超過選択後は、保持した依頼解決状態から自動的に攻略処理を再開する。UIへ表示するカード名・本文・状態名・メッセージ等はHTMLエスケープ済み。

1. 対象選択・MP置換選択・同時誘発順選択は継続ハンドラへ統合済み。新しい選択種別を追加する際は、同じ継続経路へ接続する必要がある。
2. P2P参加者画面は`getPublicState()`だけから表示モデルを生成する。新しい公開カード属性やゾーンを追加する際は、シリアライザーと公開表示モデルを同時に更新する必要がある。
3. 正規ルール本文の重複・矛盾整理は完了した。以後の仕様変更は `docs/official-rules.md` と実装監査を同時に更新する。
